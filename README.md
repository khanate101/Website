# معسلات VIP 27 – VIP 27

متجر إلكتروني عربي RTL بهوية سوداء وذهبية، مبني على PHP 8.2+ وMySQL 8.

## حالة التنفيذ الحالية

هذه هي **المرحلة التأسيسية** وليست نسخة إنتاج مكتملة. الموجود حالياً:
- واجهة رئيسية عربية متجاوبة، تعرض الأقسام والمنتجات المعتمدة من قاعدة البيانات.
- صفحات عرض القسم وتفاصيل المنتج.
- سلة مشتريات تعتمد على جلسة آمنة وتعيد التحقق من توفر المنتج.
- نموذج أولي لإتمام الطلب ينشئ الطلب وبنوده داخل MySQL transaction، مع لقطة سعر واسم المنتج ومفتاح منع تكرار الطلب.
- مخطط قاعدة بيانات أولي يشمل المستخدمين والأدوار والصلاحيات والمنتجات والطلبات والمخزون وسجل التدقيق.
- لوحة إدارة الأقسام والمنتجات، الطلبات والمخزون، والمستخدمين والصلاحيات الفردية والإعدادات الأساسية.
- بحث في المنتجات، ورسوم توصيل مضبوطة من لوحة الإدارة، وسجل تدقيق.
- إنشاء المدير الرئيسي عبر أمر CLI، دون كلمة مرور افتراضية مضمنة.

**التحديث الحالي:** سلايدر بنرات قابل للإدارة، معرض صور متعدد للمنتج، صفحات المحتوى والسياسات، رسوم التوصيل حسب المناطق، تقارير متقدمة، بوابة تحقق عمرية قابلة للتهيئة بعد مراجعة قانونية، واختبارات تكامل ومتصفح وتزامن فعلية على MySQL. المشروع ما زال نسخة تطويرية وليس جاهزاً للإنتاج أو لاستقبال طلبات حقيقية.

## المتطلبات

- PHP 8.2 أو أحدث.
- MySQL 8.0 أو أحدث.
- Composer.
- PHP extensions: pdo, pdo_mysql, fileinfo, mbstring.
- HTTPS في بيئة الإنتاج.

## التثبيت

1. أنشئ قاعدة بيانات ومستخدماً مخصصاً لها في MySQL.
2. استورد المخطط: `mysql -u DB_USER -p < database/schema.sql`.
3. أضف صلاحيات الأدوار: `mysql -u DB_USER -p alfakhamah < database/permissions.sql`.
4. انسخ `.env.example` إلى `.env`، ثم أدخل بيانات الاتصال الصحيحة.
5. اضبط `SESSION_SECURE=true` على HTTPS. للاختبار المحلي عبر HTTP فقط، اضبطها مؤقتاً إلى `false`.
6. نفّذ `composer install --no-dev --optimize-autoloader`.
7. اجعل مجلد `public/` هو Document Root، ولا تجعل جذر المستودع متاحاً من الويب.
8. أنشئ المدير من الطرفية:
   `php bin/create-admin.php admin@example.com "اسم المدير"`
   أدخل كلمة مرور قوية لا تقل عن 12 حرفاً عندما يطلبها الأمر.
9. افتح `/admin/login.php`.

## إعداد قاعدة البيانات

عدّل القيم التالية في `.env`: `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS`.
لا ترفع ملف `.env` إلى GitHub. لا تضع بيانات اعتماد حقيقية في المستودع.

## إعداد الاستضافة

- استخدم PHP-FPM أو Apache مع PHP 8.2+.
- عيّن Document Root إلى `public/`.
- امنع الوصول العام إلى `.env`, `database/`, `app/`, `bin/`, `vendor/`.
- فعّل HTTPS، ونسخاً احتياطياً يومياً لقاعدة البيانات والملفات المرفوعة.
- استخدم مستخدم قاعدة بيانات بصلاحيات محدودة، ولا تستخدم حساب root للتطبيق.

## قواعد إتاحة المنتجات

لا يعرض المتجر إلا المنتجات والأقسام التي حالتها `active` و`approved`. حالة الامتثال تبدأ `pending` ولا ينبغي اعتمادها إلا بعد التحقق من الأنظمة والتراخيص والقيود العمرية ذات الصلة. موافقة النظام لا تُستنتج تلقائياً من مجرد إضافة المنتج.

## النسخ الاحتياطي

مثال لتصدير قاعدة البيانات:
`mysqldump --single-transaction -u DB_USER -p DB_NAME > backup.sql`

احفظ النسخ خارج مجلد الويب، واختبر الاستعادة دورياً.

## الاختبارات

أُضيف GitHub Actions للتحقق من Composer وPHP lint. هذا لا يثبت سلامة تدفقات MySQL أو تجربة المتصفح. يجب اختبار استيراد المخطط والملف `database/permissions.sql` ومسارات السلة والطلب وحجز المخزون وتحريره والطلبات المتزامنة على MySQL 8 قبل النشر.
